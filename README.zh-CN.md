# Agent Pulse

[English](README.md) | **简体中文**

AI 智能体会话的脉搏监视器。Agent Pulse 是一个运行在本地的桌面工作台，帮助你集中查看智能体会话的进展、等待输入和完成状态，基于 React、TypeScript 和 Electron 构建。

名称中的 **Agent** 指 AI 智能体，**Pulse** 意为“脉搏”：通过观察会话活动，了解各个智能体的当前状态。这里的“脉搏”是产品比喻，并非进程心跳检测。

桌面应用已包含一个**实验性的、只读的 VS Code / GitHub Copilot 适配器**，活跃请求保持每两秒检查，配合文件变更唤醒和非活跃历史的退避机制，读取本地 Copilot 会话事件和已保存的聊天请求状态。浏览器预览与独立的 Demo 数据源仍使用示例数据。Claude Code 和 Codex 尚未接入。

## 运行

请使用 Node.js 24 LTS 或更新版本。目前桌面应用在 Windows 上经过测试。

```sh
npm install
npm run dev
```

Vite 会输出浏览器预览地址；若首选端口被占用，会自动选择其他端口。

```sh
npm run desktop
```

该命令会构建界面并启动桌面应用。需要热更新的桌面开发模式可使用：

```sh
npm run desktop:dev
```

## Windows 安装程序

运行以下命令生成 x64 安装程序：

```sh
npm run dist:win
```

产物为 `release/Agent-Pulse-Setup-<版本>-x64.exe`。双击后按当前用户安装，不需要管理员提权，可选择安装目录，并创建桌面和开始菜单快捷方式。应用 EXE、原生窗口与快捷方式使用 Pulse 图标；默认卸载时保留本地应用数据。

当前是未签名的开发版，Windows 可能显示未知发布者或 SmartScreen 提示。代码签名仍待完善；不要为来源不可信的程序关闭系统安全保护。当前构建命令只生成 Windows x64 版本。

首次启动安装版前，先从托盘退出正在运行的开发版，否则单实例锁可能继续激活旧的 `electron.exe`。如果任务栏以前固定的是 Electron 快捷方式，取消固定后重新固定安装版 Agent Pulse。开发命令仍使用 Electron 通用 EXE，和安装版的可执行文件图标不是同一层配置。

配套扩展随包放在安装目录的 `resources/companion/pulse-companion.vsix`，可用 VS Code 的 **Extensions: Install from VSIX** 明确安装。桌面安装程序不会悄悄安装或重载编辑器扩展；仅更新桌面打包时，已有 Companion 用户不必重新安装扩展。

发布产物不加入 Git。包内只包含编译后的界面、Electron 代码、桥接客户端与图标资源，不包含开发源码、测试、本地规划或构建依赖。已实际生成安装包并运行打包后的 EXE 做冒烟检查；未在开发机器上执行安装 / 卸载向导。

## VS Code 数据源

桌面应用默认选择 VS Code 数据源，从 VS Code 用户存储中发现本地项目文件夹和已保存的 `.code-workspace` 工作区。Windows 上的默认位置为 `%APPDATA%\Code\User\workspaceStorage`。与 VS Code 同时打开应用，找到你的项目，然后使用 Mini monitor 将监视器放在屏幕边缘。可在 Settings 中开启系统通知，接收输入请求、回复结束和会话错误提醒。

适配器增量读取 `GitHub.copilot-chat/transcripts/*.jsonl`，最多显示最近 100 个有会话记录的会话，每个会话保留最近 40 条时间线事件。会话 ID 包含工作区标识。适配器还会增量读取对应的 `chatSessions/*.jsonl` 记录，获取已保存的标题和最新请求状态。如果存在已保存的 `customTitle`，则将其作为显示标题；否则使用会话中的用户消息或通用名称。后续读取会同步已保存标题的变化。请求状态可补充会话事件中缺失的完成、取消、错误和等待输入信号。

轻量目录发现和快照发布每两秒运行一次，以便及时显示新建或已移除的会话。**In progress、Needs input，以及未结束但显示 No recent activity 的会话始终保持每 2 秒检查**，不会因为长时间没有日志而降频。其余会话（包括已结束的历史）随空闲时间退避：不足 30 秒时每 2 秒，不足 2 分钟时每 5 秒，不足 10 分钟时每 15 秒，之后每 60 秒。会话事件目录或已保存聊天目录发生变更时，受影响的会话会在下一次目录发现时被唤醒。新的会话事件活动或更新的已保存请求会恢复快速检查。如果文件系统通知不可用或遗漏，仍由有上限的轮询间隔兜底。手动 Refresh 和切换到 VS Code 数据源会跳过空闲等待。尚未写完的数据或未读完的积压记录保持快速轮询。这是调度间隔，不是实时响应保证，磁盘读取与首次加载历史可能增加延迟。

卡片、侧边监视器和会话详情中的 **Idle** 表示距离最近一次观察到会话活动的时间，每秒更新，无须重新读取日志。回复结束后它会继续增长，出现更新的事件时重置。这并不代表智能体实际没有在工作。详情中另有 **Elapsed**，表示已观察到的耗时，并在观察到回复结束时停止计时。

使用 VS Code Insiders、便携版或其他用户数据目录时，请在启动前设置存储根目录。例如，在 PowerShell 中：

```powershell
$env:PULSE_VSCODE_STORAGE = Join-Path $env:APPDATA 'Code - Insiders\User\workspaceStorage'
$env:PULSE_VSCODE_SCHEME = 'vscode-insiders'
npm run desktop
```

仅支持 `vscode` 和 `vscode-insiders` URL 协议。存储目录缺失或不可读时，应用会明确提示，不会用示例会话替代连接失败的真实数据。不写入此会话记录格式的 VS Code 版本、未命名工作区、仅包含远程 URI 的工作区，以及其他提供方，均不在此适配器的支持范围内。

### 状态含义

| 界面状态           | 中文含义   | 判断依据                                                                                                                                               |
| ------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| In progress        | 进行中     | 用户消息、助手轮次或工具事件处于活动状态，或更新的已保存请求已经开始。                                                                                 |
| Needs input        | 等待输入   | 已知的提问工具（如 `vscode_askQuestions`）正在等待响应，或当前已保存请求标记为需要输入。                                                               |
| Rely Ready         | 输出已就绪 | 不包含工具请求的非空助手回复之后出现轮次结束事件且没有待完成的工具，或当前已保存请求记录了正常结束。这仅表示有输出可查看，不代表任务成功或会话已归档。 |
| Failed             | 会话出错   | 出现明确的 `session.error` 事件，或已结束的保存请求带有错误标记。单个工具失败不会直接判定会话失败，因为智能体可能自行恢复。                            |
| Stopped            | 已停止     | 当前已保存请求记录了取消状态。                                                                                                                         |
| No recent activity | 无近期活动 | 此前处于运行状态，但已两分钟没有新活动，也没有完成信号。智能体可能仍在工作。                                                                           |
| Status unknown     | 状态未知   | 生命周期证据不完整，或日志更新尚未写完。静默绝不等于完成。                                                                                             |

这些状态根据内部文件推断，可能随版本变化；它们不是官方 Copilot 生命周期 API，也不是 VS Code 进程心跳。部分权限提示、取消操作和最终回复可能在两类记录中都缺失。没有完成信号时，会话可能停留在无近期活动或状态未知；已观察到的输入请求可能一直显示为等待输入，直到后续更新将其解除。历史会话记录会继续显示，不一定对应当前打开的聊天。应用不会推断分支或文件变更数量，耗时从最早观察到的会话事件开始计算。

**Open in VS Code 通过 Pulse Companion 0.4 使用已经打开的工作区窗口。** 不通过 `vscode://file` URL 新开窗口；Companion 聚焦自己的已有窗口，并等待异步标签事件确认侧栏移动。未注册、管道失效、超时、会话不存在和导航失败分别提示。聚焦原工作区窗口或运行 **Pulse: Show Connection Status** 会刷新连接注册；更新已激活的扩展后仍需重载 VS Code。侧栏不可用时保留编辑器回退，不自动创建新窗口，也不发送消息或批准权限。

在本仓库中打包并安装本地配套扩展：

```sh
npm --prefix vscode-companion run package
code --install-extension .artifacts/pulse-companion.vsix --force
```

若扩展尚未激活，在 VS Code 中运行 **Pulse: Show Connection Status**。扩展通过带随机令牌的本地管道按工作区路由，不创建公网监听服务。已在本机验证当前版本的内部 chat URI；其他 VS Code 版本的兼容性仍属实验性。

**状态变化提醒**由 Electron 主进程负责：需要输入或输出就绪时，在显示器顶部居中出现轻量提示，不抢键盘焦点，约 5 秒后淡出，鼠标悬停时暂停。同一批变化合并展示，不连续轮播以前未处理的提醒。淡出或关闭只隐藏提示，不标记已读、不归档、不丢弃待处理记录；顶部铃铛可以重新打开。等待输入解除后撤销过期提示。监控期间 Pulse 需要保持运行，可以驻留托盘。

系统通知是 Settings 中的可选补充渠道，默认关闭，避免双重弹窗；旧版通知偏好会一次性迁移为这一较安静的默认值。Pulse 自己的顶部提示仍启用，不再闪烁任务栏。

铃铛、托盘和提示的 `+N more` 会打开稳定的待处理列表，等待输入优先，每一条都可单独跳转或忽略；忽略不等于已读或归档，跳转失败会在对应项目下显示原因。首次输入请求静默入队，历史完成记录不弹窗。最多 200 条待处理提醒及最近去重基线会原子保存到应用本地数据，重启后静默恢复，已忽略的输入请求不会复活。已接入休眠唤醒后的强制采集和补偿弹窗抑制，真实机器的休眠兼容性仍需更多验证。损坏历史会保留备份，恢复或写入失败会在列表中提示。

跳转携带具体请求引用；过期提醒会被拒绝，旧跳转的回执不会清除新请求提醒或把新回复标为已读。新的已读记录包含请求身份和完成时间，同时兼容已有的时间戳记录。

**Rely Ready 与 Archive session 分开。** 前者是 agent 最新一轮的输出状态，后者是用户可恢复的本地归档操作。大窗真实会话详情提供 Archive session / Restore session，集合筛选可查看未归档、归档或全部会话。归档标记独立持久化，不修改 provider 状态、活动时间或源记录，也不停止监控；有活动或需处理的归档会话仍可出现在小窗。Workspace 暂时移除单独的 Replies ready 区块，输出状态仍显示在卡片和状态筛选中。已读标记与归档也是独立的。

实时快照仅保存在进程内存中，不会写入 Demo 缓存。提醒历史只在应用本地数据中保存会话 / 请求身份、标题、工作区名、状态和时间。工具参数、工具输出和推理文本不会发送到渲染进程。标题、可选的用户消息任务标签、工作区名称和事件摘要都属于本地会话信息；开启系统通知可能让项目或任务名称出现在操作系统通知中。适配器不会上传这些数据。

## 可用交互

- 在桌面工作台中切换 VS Code 和 Demo 数据源，两个原生窗口共享同一数据源。
- 搜索会话，按状态和提供方筛选，并切换网格或列表布局。
- 查看会话时间线、任务详情、耗时和实时空闲时长。
- 仅在 Demo 中运行完成演示、批准示例请求或重试示例失败；这些操作无法修改真实会话。
- 接收应用内完成提醒，并可在 Settings 中开启系统通知和声音。
- 最小化原生工作台或点击 Mini monitor 时，主窗口保持最小化并保留任务栏入口；从任务栏恢复大窗会收起小窗。关闭大窗仍是隐藏到托盘，和最小化不同。
- 将侧边监视器收起为窄任务栏，并在屏幕左右边缘之间切换。
- 在任一侧边监视器布局中点击实时任务，直接在 VS Code 中打开；Demo 任务仍恢复 Pulse 详情面板。
- 使用 Expand workspace 最大化完整面板，再次最小化后返回侧边监视器。
- 两个窗口在本地同步会话状态和偏好。实时数据由同一个 Electron 采集器提供，Demo 变更通过本地存储同步。主面板隐藏时，侧边监视器仍会显示提醒。
- 将任一原生窗口置顶于其他窗口之上。浏览器窗口无法实现系统级置顶。
- 拖动原生迷你监视器的标题栏移动窗口；滚动会话列表时，底部栏保持可见。
- 关闭原生工作台后，应用继续驻留托盘。使用托盘菜单中的“Quit Pulse”退出。

系统通知受操作系统通知设置影响。浏览器预览仅在开启通知时请求权限；打开迷你监视器需要浏览器允许弹出窗口。

浏览器预览可以显示两种紧凑布局，但无法读取本地 VS Code 会话，也无法对操作系统窗口进行贴边、最大化或置顶。原生应用中的模式切换会控制真实窗口。精确会话跳转需要桌面程序与 Pulse Companion 配合。

示例数据和偏好保存在设备本地。Reset demo 会恢复六个示例会话，在 VS Code 数据源下不可用。无需账号、遥测、外部字体或模型 API 密钥。

## 项目结构

- `src/Workspace.tsx`：完整工作台、迷你监视器和通知界面。
- `src/sessions.ts`：共享会话类型、Demo 状态转换和存储校验。
- `electron/main.cjs`：原生窗口、托盘、置顶和系统通知。
- `electron/vscode-sessions.cjs`：本地工作区发现、有界增量读取和会话状态推断。
- `electron/preload.cjs`：受限且启用上下文隔离的 IPC 桥接。
- `tests/`：浏览器工作流和原生窗口测试。

## 集成边界

当前数据路径为 `本地文件 -> 提供方适配器 -> 主进程快照 -> 隔离的 IPC -> 工作台 / 侧边监视器`。主进程负责发现会话，并在打开工作区前校验会话 ID。渲染进程无法请求任意文件系统读取或打开任意外部 URL。

若要可靠地支持权限批准和应用内回复，下一步应为各提供方建立专用桥接，在可用时使用受支持的生命周期／输入钩子，并具备经过身份验证的本地传输、稳定的会话／请求 ID、重连处理和明确的用户确认。配套 VS Code 扩展可能有助于实现受支持的导航与命令，但不能假定它可不受限制地访问所有 Copilot 聊天。添加回复或批准操作前，应先验证这些 API。会话记录适配器应始终明确标注为只读观察的后备方案，而不是执行操作的授权依据。
